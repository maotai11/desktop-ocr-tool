Python 套件歷史修補基準：rc.5（2026-11-02）；原生修補基準：rc.12（2026-11-05）；整區搜尋／預覽及位置分配更新：rc.16；浮窗狀態與背景工作收尾更新：rc.14（2026-11-11）。設定與字面替換更新：rc.17（2026-11-12）。本文件說明修正與檢查方法；每次正式發布的實際結果以同一來源版本的 validation metadata 為準。

rc.5 本機更新後的 31 個 Python distribution 掃描結果為 0 個已知漏洞；這是該次檢查紀錄，不沿用為後續版本的掃描結果。CI 會另外掃描 Linux 與 Windows 的實際安裝清單，Windows 專用套件也在範圍內。掃描工具裝在另一個環境，不包進 EXE。任何套件漏掃、資料庫查詢失敗、版本不符或發現漏洞都會阻止建置／發布；不使用忽略清單。

發布器會核對 Windows 掃描的來源 commit、安裝清單 SHA256、套件數量、掃描器版本及零發現結果。公開摘要提供套件數與清單雜湊；原始建置路徑及診斷輸出不放入公開 ZIP。

## rc.12 原生元件修補與來源核對

這次檢查實際舊版 payload，發現 Qt6Core／Gui／Network／Svg／Widgets 為 6.11.2。Python 的 pip-audit 沒有完整涵蓋這些原生 Qt 公告；先前 Python distribution 零發現不能替代 DLL 的版本核對。rc.12 將 `PySide6-Essentials` 及 `shiboken6` 鎖定至 6.11.3，並要求建置時核對 Qt runtime 與成品 PE 版本，不能只修改 requirements 就宣稱 EXE 已修好。

| 舊版實際元件 | 官方公告／影響 | rc.12 要求 |
| --- | --- | --- |
| Qt Core 6.11.2（64 位元） | CVE-2026-107157：`QCborValue::fromCbor()` 越界讀取；官方列 6.11.2 及之前的受影響分支 | Qt 6.11.3，並核對封裝版本 |
| Qt Network 6.11.2 | CVE-2026-95620：HTTP/2 use-after-free，可造成應用程式崩潰 | Qt 6.11.3，並核對封裝版本 |
| Qt Core 6.11.2 | CVE-2026-105924：CBOR 轉 JSON 的空指標問題；6.12.0 也在受影響範圍 | 採已修正的 6.11.3，沒有直接改用 6.12.0 |

來源：[Qt 官方已知漏洞表](https://wiki.qt.io/List_of_known_vulnerabilities_in_Qt_products)、[Core CBOR 公告](https://www.qt.io/blog/security-advisory-cve-2026-107157)、[Network HTTP/2 公告](https://www.qt.io/blog/security-advisory-cve-2026-95620)。本工具沒有主動使用 HTTP/2 或 CBOR 不代表可以忽略已封裝的受影響元件；會修補版本，同時保留功能測試與路徑檢查的範圍。舊 payload 未包含 Qt5Compat，不能把只影響該模組的公告列成此成品已帶入的漏洞。這份清單針對實際存在的模組及已確認公告，不是所有 Qt、第三方原生庫或未知漏洞的完整證明。

重新以發行包 SHA256 核對來源後，確認舊 EXE 的檔名未帶 `-x64` 的 `libcrypto-3.dll`／`libssl-3.dll` 3.0.16 隨 CPython 3.12.10 而來；相關檔案與 python.org 官方嵌入包相符。舊包另有的 `libcrypto-3-x64.dll`／`libssl-3-x64.dll` 3.5.9 才是 Qt 打包時外帶的另一份依賴。兩者必須分別記錄來源，不能以檔名、PATH 或另一份 OpenSSL 的新版本代證。上游 [OpenSSL 3.5 公告](https://www.openssl-library.org/news/vulnerabilities-3.5/) 列出 2026-09-29 修正在 3.5.9 的問題；較舊的 3.0.16 不能當成已含後續修正。

rc.12 更換 Windows 的 Python 執行環境，採 [Astral python-build-standalone](https://github.com/astral-sh/python-build-standalone) 的 CPython 3.12.16／20261026 Windows 發行包；供應來源為 Astral，並非 python.org 官方安裝器。鎖定壓縮包 SHA256 為 `1f2ab53880fc67ea323398c6388e05af28addc99a8e389209f08a51fdff4b149`，包內 `python312.dll` 為 3.12.16，動態 `libcrypto-3-x64.dll`／`libssl-3-x64.dll` 為 3.5.9。建置 bootstrap 要求整包 SHA256 與 PE 清單相符，再用隔離的 runtime smoke 核對 Python／OpenSSL 版本及 `_ssl`／`_hashlib` 來源；這些條件不能代替新 Windows 成品的功能或 Defender 掃描通過。

更換 runtime 修補 Python SSL 依賴；排除未使用的 Qt TLS plugins 與外帶 OpenSSL 是另一項縮減封裝範圍的措施。成品清冊仍須確認每個 DLL 確實來自新鎖定來源，不能直接沿用舊包中相同名稱的 3.5.9。沒有修改使用者系統的 OpenSSL，也沒有觀察到漏洞利用；發現的是舊成品曾包含未含後續修正的版本。

Windows 建置入口為 `scripts/prepare_windows_runtime.py --destination <系統暫存新目錄> --report artifacts/windows-runtime-inventory.json`，成功後只印出已驗證的絕對 `python.exe` 路徑，後續 pip／prepare／build 使用該路徑。本機不修改全域環境；CI 只寫入當次 job 的 GitHub 環境檔。

Linux 開發／測試仍使用 Python 3.12，Windows 發布固定 3.12.16；RapidOCR 1.4.4 要求 Python < 3.13。發行包下載及核對只在建置機執行，離線使用電腦不需安裝 Python，也不啟動 runtime 下載器。這份版本選擇與已確認公告核對，不代表所有 CPython 內嵌元件的完整 CVE／SBOM 審查。

rc.12 新增成品 PE 清冊、來源／匯入／簽章及 Windows Defender 檢查，與 Python 套件稽核分開報告。每一項的實際範圍、結果狀態及未完成的原生 SBOM 限制見 [本版驗證範圍](VALIDATION_COVERAGE.md)。清冊完整、簽章存在、掃描無偵測分別回答不同問題，不能合併寫成「全部 DLL 無漏洞」。

原生稽核的 Windows 實跑也暴露出檢查器本身的限制：pefile 預設只解析 8,192 個匯出項目，會截斷 Qt／OpenBLAS 較大的匯出表。現改為 131,072 個符號的有界完整解析，先核對原始表格位址、長度、名稱與 ordinal 數目，再比對解析結果；超界、截斷或數目不符都失敗，不把讀到上限當作已完整檢查。

API-set 依實際 Windows namespace 的 hash／修訂結構解析，以真實匯入者的 basename 做不分大小寫的完整名稱比對，選取該 alias 的唯一 host；沒有對應 alias 時只採唯一有效的預設 host。匯入者未知且 host 有分歧，或當下必須採用的 alias／預設缺失或不唯一時，不將不同 host 混成可用清單或猜測選擇，保留未解析並拒絕通過。Common Controls 6 的 `comctl32.dll` 則依候選 EXE 實際 manifest 建立 activation context，只查詢中繼資料來選定 WinSxS 元件，不載入待檢查元件或執行其程式碼。清冊以 `windows_sxs` 記錄受限相對 `target` 與 `target_sha256`，目標 PE 另核對 AMD64；不靠搜尋任意 WinSxS 版本替代。

封裝完成 Analysis 後，只對明列的 43 個 `api-ms-win-core`／`api-ms-win-crt` 相容 stub 及 `ucrtbase.dll` 套用條件排除。必須在 Windows 10+ 以實際 API-set／System32 證明保留檔案對這份候選清單的所有顯式匯入，以及保留 bundled DLL 指向候選的相關 export forwarder 鏈都可被系統滿足，並對深度、符號數及循環設限。無法證明的檔案保留，再由嚴格原生來源 gate 阻止未知來源通過；一般 `msvcp`／`vcruntime`／SSL 依賴不在這份排除清單內。

直接匯入與保留 bundled DLL 的轉送證明都帶入真實匯入者名稱；進入 OS forwarder 後，下一步改用實際 OS 父模組的 basename。沒有已觀察到請求者的 API 候選，不虛構一個匯入者；必須有唯一有效預設，並確認 schema 列出的所有有限 host 選擇都對應可用的 AMD64 系統 DLL，任一缺失或衝突就保留。這項無請求者檢查只用於排除政策，不能拿來替未知匯入者選定某個分歧 host。

這 44 個舊相容檔的第三方供應來源仍未知，排除依據是可驗證的系統替代，不是對未知供應者的核准。這些規則不刪 Windows 系統檔，也不證明所有 DLL 已載入或所有程式路徑已執行。新解析／SxS／封裝政策及 Defender 是否實際通過，仍須看同版 Windows 報告，不能把規則或測試設計當成已通過。

本次 Windows 只讀診斷確認 Defender 服務及防毒啟用、本機掃描設定符合要求，但病毒碼約 151 小時，超出 72 小時門檻，因此不能當成掃描通過。建置驗證只在病毒碼過期時，先確認服務、隱私設定及官方 `MpCmdRun.exe` 的 Microsoft 有效簽章，再執行 `-SignatureUpdate -MMPC`，最多等待 180 秒；完成後重新讀取狀態，仍須符合原本 72 小時門檻。更新失敗、逾時或仍過期都停止驗證，不降低門檻。

這是建置機的病毒碼維護，不修改 Defender 防護設定、不加入排除，也不建立排程、應用程式更新器或背景工作。原始更新輸出僅留在 runner 的本次暫存並於結束清理。是否實際更新及完成掃描，須讀同次報告；這段機制說明不是更新或掃描已成功的證據。

## rc.10 自動封存與資料保留

`history.auto_archive_days` 原本只有預設值，rc.10 才接上實際排程。新安裝預設 90 天，可在「設定 → 一般 → 自動封存」設為 0 停用，儲存後立即套用。程式啟動及每日檢查，以紀錄最後修改時間判斷是否已滿設定天數；查看或複製不延長日期，真正修改文字、筆記、標籤關聯或手動還原會更新時間。

封存只改 `is_archived` 與修改時間，不刪文字、原圖或附件，也不釋出附件占用的磁碟空間。釘選、已刪除、已封存、OCR pending／processing，以及有尚未完成 OCR 工作的紀錄均排除；無效時間格式不自動處理。每批最多 200 筆，使用資料庫工作執行緒與專用索引，不用 GUI 逐筆掃描或另開 OCR 引擎。選取候選與更新均在交易內檢查條件，取消會在提交前回滾該批；設定變更與退出會撤銷舊 generation、停止後續批次。退出流程先等待工作回覆，再關閉資料庫。

排程在同一天合併重複要求；沒有候選或發生錯誤後，不用短週期持續重試。FTS 更新觸發器已升級，只有索引文字欄位更新才重建對應全文索引，單純封存不重建未改動的文字。既有資料庫會保留歷史與全文內容，新增整理索引及觸發器接線。

「已歸檔」分類只列封存紀錄，可右鍵「取消歸檔」還原。普通刪除仍是軟刪除；「清理已刪除」才永久刪除資料及附件，另存的匯出副本不跟著刪。`history.max_items` 與 `history.auto_delete_archived_days` 沒有實作自動刪除，已退出新預設設定；不因這次修正開始依總筆數或封存天數永久清資料。

舊版異常中斷後留下的 pending 工作沒有程序 PID／session／啟動時間可證明擁有者已結束，尤其 `single_instance=False` 時可能來自另一個仍在運行的程序。因此本版不批量改成完成或失敗，也不自動重跑；它們仍排除於自動封存，使用者可手動重辨。這是保留資料的限制，不是已完成的自動孤兒回收功能。

## rc.10 即時設定與有限節點掃描

剪貼簿監看與文字收錄原本只在啟動讀取一次。rc.10 改由單一生命週期控制器在設定儲存後立即建立或卸除監聽器；監看關閉、文字收錄關閉或手動暫停都會停止接收。舊回呼依 generation 與當下設定再次檢查，退出後不能重新啟用；重新開啟只收錄之後的變化，不回填當前剪貼簿。圖片監聽仍未支援，不因接線修正而自動開啟。浮窗與系統匣的暫停勾選同步。

浮窗、主控台、編輯器及標籤變更共用歷史失效通知，封存／刪除／釘選／編輯後同步刷新已開視窗，保留主控台的搜尋、分類及仍有效的選取。標籤管理原本即時寫入的操作也會立即通知；取消其他設定不會把已完成的標籤變更當作未發生。

rc.10 的掃描範圍包含設定消費點、UI action／signal、工作者生命週期、CLI、工作流程及 Git 旁支。以 rc.9 `92c2972` 為掃描起點，當時 15 個分支中的 14 個舊分支 head 都是 master 祖先、沒有分支獨有提交；PR #1–#12 均已合併，沒有自動重併或刪除遠端分支。已移除未被引用的舊 AppSignals bus 與已完成任務的 rc.3 README 單次 workflow；現行固定版本發布 marker 是刻意的發布限制。

27 個沒有接入 Core 的新預設設定已退休，原因列在 `RETIRED_CORE_SETTINGS`；舊 JSON 額外欄位仍可讀回與儲存，不會因此啟用實驗引擎或刪掉舊設定。可選 Paddle／CnOCR 及舊預處理 API 是保留的擴充介面，核心 EXE 不會因掃描而載入它們。主題、字體與圖片剪貼簿的未支援控制維持明確停用。詳細分類見 [設定接線與節點稽核](CONFIG_WIRING_MATRIX.md)。這是針對已列路徑的有限檢查，不能當作所有動態分支的形式證明。

## rc.14 浮窗關閉與晚到工作

這次實際重現了隱藏手寫窗仍送出延遲辨識、helper 失敗後立即重試被舊結束通知丟棄、取消框選後沿用舊手勢，以及核對通知內暫停／重開被舊流程干擾。修正使隱藏／關閉先退役該次工作，回覆與等待操作核對目前輪次；退出期間不接受新工具入口，已結束的設定／標籤模態返回也不能再寫設定或 DB。

正常關閉編輯器不擅自保存草稿，最小化後還原則保留既有草稿。已接受的儲存與單次原生辨識仍依既有收尾規則完成，不能解讀為強制立刻中止所有工作。這些修正不加入網路連線、執行資料檔或新常駐輪詢。逐項操作、回歸依據與未覆蓋範圍見 [浮窗狀態檢查](FLOATING_STATE_AUDIT.md)；正式完成狀態仍以同版報告為準。

## 整列搜尋與選取列跟隨（rc.11 加入，rc.16 更新）

「整列搜尋」是與原有固定位置 A／B 核對分開的控制流程。預設 A 整區整理最多 100 列、每列 20 值；逐欄模式最多 20 欄。每值最多一個 B 位置，同一或高度重疊位置不重複分配；多個確切候選需選取，近似可顯示暫定位置但維持需確認。全部 A 共用比對方式；一般模式的數字片段仍保留正負號、小數點、千分位、百分號及前導零，不將 O／I 猜成 0／1。文字相似門檻固定 95%，與 OCR 信心分開判斷；逐字模式停用近似與日期換算，原有複製清理設定不會先改掉待比對原文。近似候選即使唯一或經手選也維持需要確認，A／B 原始 OCR 的 needs_review 分別阻擋確定命中；行級框不宣稱行內重複數字的逐字定位。

數字近似限至少兩位、相同位數／格式及前導零數量；整區模式至少 60% 位數相同，逐欄模式沿用只差一位。分數為相同數字位數比例，永遠需要確認。日期換算只接受已支援中文年制與有效年月日，保留原文及低信心限制；兩輪獨立檢查修正已知不支援年制前綴與一般文字匹配繞過日期規則的路徑。這是有限規則測試，不是任意日期或模型準確率證明。

開窗、框選不自動搜尋；「開始搜尋」或手動上一列／下一列才啟動畫面檢查與辨識，校正另做一次表格取樣。共用原有 OCR 工作者，不另建模型。A／B 取自包住已選範圍的一張共用快照，範圍間畫素也可能短暫存在記憶體，裁切後依序處理且不留檔。輸出前再擷取確認畫面；A、B、列位置或內容改變時丟棄過期結果。B 只有像素與辨識設定相同才可重用一份有界的記憶體 OCR 結果快取，不把相同 Y 座標當成相同資料。A 換列而 B 未變只重辨 A；A／B 都未變略過 OCR。搜尋中的手動辨識保留位置、撤銷舊輪並重辨 B 及 A，快速連按不增開並行模型；暫停或關閉後不接受此入口。

自動跟隨限使用者框選的表格範圍，需先校正當前選取列及 A 的相對位置。新選取底色連續兩次畫面檢查穩定後才跟隨；同一 Y 座標的新內容仍重新辨識。這是畫面底色追蹤，不是其他軟體的資料庫／控制項存取，不自動替目標軟體按鍵、點列或捲頁。底色不明、多處候選或越界不採用猜測位置，應重新校正或手動換列。主題、斑馬紋及不等高列會影響可靠性。位置不明時仍可能按間隔擷取、等待穩定，並非已暫停；使用者按暫停／關閉才停止後續檢查。此功能沒有全鍵盤記錄 hook。

rc.16 把 A 原值與比對百分比優先放在選定 B OCR 文字框下方，相似候選可改放緊鄰側邊；A 目前列另顯示箭頭，沒有選定候選或安全空間時回控制窗查看，不發明位置。開始後收起控制窗，保留「手動辨識／恢復介面」兩個小按鈕。背景透明度預設 100%，只改底板、不把文字透明或觸發 OCR；改外觀不會恢復已暫停標示。文字點擊穿透，按鈕可點擊；恢復控制窗後可暫停或改框。置頂只套用桌面文字與按鈕，控制窗維持一般視窗；視窗顯示／擷取恢復時重套用原設定，不另開持續搶前景的輪詢。擷取時同時隱藏文字與按鈕，停止或關閉清除；長文會省略，完整結果可在控制窗查看。透明或置頂不能讀到被遮住的原文。本版沿用主螢幕框選限制，不宣稱支援任意混合 DPI 多螢幕追蹤。

暫停、改框、清除或關閉會撤銷當前工作、清除過期結果及標示，停止後續列與輪次；已進入原生 OCR 的單次呼叫仍需返回。遲到結果不恢復舊標示或重開視窗。關閉後不持續追蹤，退出由原有 Pipeline 管理工作者停止。進行中需要定期擷取／摘要及定位，並非零背景成本。

「預覽／調整」由明確點擊觸發，先暫停並隱藏標示，再擷取一張完整主螢幕影像以支援移動範圍；不持續取圖。影像與裁切預覽只在對話框記憶體，取消／套用／關閉清除；只有有效且仍屬當次的接受操作能套用座標。

座標、列高校正、結果與有界快取只留本次執行記憶體，當輪暫時影像完成／取消後釋放。不把 A／B 圖片、OCR 文字或候選寫入歷史、剪貼簿、匯出、內容 Log 或檔案，也不上傳；一般操作錯誤仍可能留下不含內容的診斷。沒有新模型或表格結構引擎，並未新增執行時下載依賴。具體操作見 [整列搜尋](SHARED_SEARCH.md)。新版必須提供新增路徑的同版驗證，舊固定位置核對的成功證據不能直接沿用為新模式通過。

## A／B 多組核對與停止行為

rc.7 已加入畫面不變時跳過 OCR 與關窗停止；rc.8 延伸為最多 20 組命名 A／B，仍只有使用者明確開始後才執行。開啟應用程式或核對窗、選擇設定／全文組別都不會自行啟動辨識。名稱、位置與結果只留在本次執行的記憶體，退出後不恢復。

整批按組別順序執行，共用單一擷取工作者與原本的 OCR 佇列；每組 A／B 取自同一張快照，組與組依序擷取，不宣稱所有組別同時取樣。擷取執行緒各自計算每組 BLAKE2b 32-byte 摘要；該組兩區像素都不變便跳過 OCR，不增加該組次數或刷新時間。全部組別走完後才等待設定間隔，不平行啟動多個模型或累積未處理輪次。等待時每組只保留摘要，不保留畫面快取。

新增、更名、移除組別、重新框選或變更比對規則會先暫停全部組別；選擇設定／全文組別不會重新定位正在擷取的範圍。螢幕配置變動會清掉全部位置。擷取前檢查核對窗與其他本工具視窗是否遮住任一組目標，遮住時暫停，避免辨識到工具本身。

暫停、關閉核對窗或退出程式時，會停止核對計時器、清除全部組別的摘要與待處理影像，取消後續區域、組別及輪次並忽略過期結果。已進入原生辨識的單次呼叫仍需先返回，但會在下一個邊界停止補辨、後續切片及第二引擎。UI 不等待原生呼叫即可關閉；遲到結果與框選回呼不會重開視窗。核對圖片與結果不寫入歷史、剪貼簿或內容 Log，也不傳送到網路。

等待變化期間仍會定期擷取全部已設定組別並計算摘要，組別增加會增加每批處理時間；這是使用者啟動的監看，並非完全零工作。暫停或關窗後連畫面檢查也停止。共用 OCR 模型及閒置執行緒可能保留供其他功能使用，其等待採阻塞方式，不做 CPU 忙等。發布證據應包含當版來源／frozen／隔離探針與組別序列、結果隔離、畫面跳過及整批取消的檢查，不沿用前版成功紀錄代替。

rc.9 的「迷你」只切換呈現方式，不另建辨識工作者或自動啟動核對。rc.10 多組卡片同時呈現各組 A／B 文字、狀態與時間，單一組的新結果不改寫其他組或跳動捲動位置；設定選單只用於編輯／全文。一般尺寸可完整看到約 3 組，迷你至少 2 組，更多直接捲動，不代表同時取樣或平行推論。單組仍沿用兩區版面。還原後若遮住任一框選範圍，遮擋檢查仍會暫停；Windows 最小化則隱藏視窗並繼續已啟動的核對。

rc.10 固定位置核對使用來源／frozen／隔離探針的 20 項檢查，含多組同時可見及個別更新；這個數量不代表 rc.11 新模式的覆蓋。新版本須提供自己新增路徑的同版證據，應用程式啟閉探針仍要求歷史整理控制器已停止。合成流程驗證介面與生命週期，不宣稱 OCR 準確率或乾淨實機驗收。

## 複製清理與原文範圍

rc.17 延續原有四個啟用布林設定，預設關閉且處理方式預設移除；另外儲存各列的移除／替換選擇及最多 64 個 Unicode 字元的字面字串。不是正規表示式、命令或範本，不執行使用者字串。設定仍在既有本機 settings.json，不另建資料檔、模型、網路或背景輪詢。

清理對原文只走一次；已啟用的逗號／撇號／換行優先於所有標點與空白，插入文字不再次處理，CRLF 算一次。控制字元、代理碼及 Unicode 行／段分隔不能作為替代值；啟用替換或編輯文字時先驗證全部規則，失敗不先寫其他設定。手動破壞設定檔造成未知動作或無效替代值時，受影響類別保留原字元，不能靜默變成移除；未提供新動作欄位的舊設定仍採移除。

一般 OCR／歷史複製與 `FloatingWidget.paste_last_item` 準備貼上最後一筆時使用規則；不改資料庫原文。文件套版複製、模板、逐頁結果、TXT 預覽與匯出均維持原文，手寫候選保留原字，模擬貼上與還原剪貼簿的低階路徑不再重複清理，A／B 核對規則也獨立。單獨換行移除保留筆間空行；明確換行替換會處理分隔的兩個換行。所有標點仍可能移除小數點與半形負號，不能視為不影響數值格式。

## 功能結束後的程序與工作

- 手寫原生 helper 在回傳候選後收到結束訊號並被回收，不再一直留在背景等下一次。下一次書寫重新啟動；逾期未結束的程序會被終止。
- 新筆畫、清除或重新辨識會取消過期手寫要求；晚到結果不能改寫新結果。影像補辨也有獨立程序、期限與回收機制。
- OCR 模型載入後仍留在記憶體供下一次操作使用，但 ONNX Runtime 的執行緒等待已停用 CPU spinning，閒置時採阻塞等待。
- 文件的停止、清除與關窗會取消後續頁面、移除佇列並丟棄舊結果。正在 QThread 內執行的原生 PDF／OCR 呼叫需先返回，不能安全地強制打斷；這個限制仍存在。
- 90 天自動封存啟動後只在啟動／每日或設定變更時排程，分批結束便回到閒置；停用或退出會停止後續要求。
- 系統匣、全域快捷鍵、資料庫與工作佇列等待是程式正常功能。關閉功能視窗不等於退出程式；要全部結束請從系統匣選「退出」。剪貼簿監看預設關閉，只有使用者啟用後才持續監看。
- 停用 ONNX 遙測及本工具不需要的 OpenEXR、Jasper、FFmpeg、GStreamer 路徑。模型只在建置時準備，應用程式不自動下載模型或更新。

## 在建置機重跑

安裝依賴並產生 `artifacts/dependency-inventory.json` 後，在獨立 venv 安裝 `requirements-security.txt`，使用應用程式的 Python 執行：

```sh
python scripts/audit_dependencies.py --inventory artifacts/dependency-inventory.json --tool-python <掃描用venv的Python路徑> --report artifacts/security-audit.json
# Linux，需先安裝 strace、準備模型與原生 helper：
python scripts/audit_runtime_network.py --report artifacts/runtime-network-audit.json
```

CI 會自動設定來源版本並執行相同指令；離線使用者不需執行或安裝掃描工具。這些 GUI／原生／Defender 探針只在建置與驗證時執行，應用程式一般使用流程不會在背景啟動它們。

GUI 操作使用 `python src/main.py --self-test-gui source-gui.json`，報告 16 個具名控制流程；固定位置核對及整列搜尋另用 `--self-test-comparison`、`--self-test-shared-search`。Windows 建置後由 `scripts/validate_native_payload.ps1` 對同版 EXE 執行原生清冊、來源／匯入／簽章及 Defender，再由發佈器重新核對檔案與範圍雜湊。只跑 `audit_native_payload.py` 的靜態階段，不能代替 Windows 簽章與防毒完成。具體欄位、16 項 GUI 操作與人工剩餘在 [驗證矩陣](VALIDATION_COVERAGE.md)。
