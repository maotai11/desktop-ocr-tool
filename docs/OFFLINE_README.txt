InkPick 拾字筆 v1.8.0-rc.17
完整離線操作說明
========================================

這份說明不需要網路、圖片或外部文件，即可完成主要操作。
本版整理設定分區，複製清理四列可各選移除／替換並輸入自訂文字；
儲存後套用一般 OCR／歷史複製；文件套版、手寫候選與匯出維持原文。
本版可整區框選 A 的多列輸入值，用目前列箭頭與上一列／下一列核對發票 B。
近似候選以橘色顯示，同一 B 位置只配給一個值；可預覽／調整框選範圍。
開始搜尋後控制窗收起，留下可調背景透明度的標示及「手動辨識／恢復介面」按鈕。
點回來源文件後標示持續可見；要暫停或改位置，先按「恢復介面」。
原有多 A 共用 B、換列跟隨、固定位置 A／B 核對、90 天封存及文件套版保留。
ZIP 內 OFFLINE_README.txt 與 README.txt 內容相同；Release 單獨提供的
InkPick-v1.8.0-rc.17-README.txt 也是同一份 UTF-8（含 BOM）文字說明。

沿用前版的操作修正

一、下載、核對與啟動
----------------------------------------
適用 Windows 10 1809 以上／Windows 11，64 位元。
EXE 已包含 Python、Qt、PDFium、兩組 OCR 模型與手寫引擎。
使用電腦不需安裝 Python、pip、PDF 閱讀器、Windows 手寫語言套件，
首次執行也不需要下載模型，可以斷網使用。

1. 在能上網的電腦下載同版 InkPick-v1.8.0-rc.17.zip，再用隨身碟帶到離線電腦。
2. 將整份 ZIP 解壓到有寫入權限的資料夾，例如 D:\Tools\InkPick。
   不要直接在 ZIP 裡執行，也不要放在受保護的 Program Files。
3. 執行 InkPick-v1.8.0-rc.17.exe，不需要管理員權限。
4. 預設會縮到右下角系統匣。點拾字筆圖示顯示／隱藏浮動窗；
   也可在圖示按右鍵，選擇功能。浮動窗出現「可擷取文字」後可開始。
5. 第一次執行會先解開內含資源、載入模型，請等待完成。
   結束程式請從系統匣選「退出」，讓辨識、儲存與背景程序先結束。

同版下載檔案：
- InkPick-v1.8.0-rc.17.zip：EXE、離線說明、文件套版圖文說明、授權及模型來源。
- InkPick-v1.8.0-rc.17.exe：單獨的相同執行檔，已內含所需執行環境與模型。
- InkPick-v1.8.0-rc.17-README.txt：本份離線操作說明。
- InkPick-v1.8.0-rc.17-SHA256SUMS.txt：同版檔案 SHA256。
- InkPick-v1.8.0-rc.17-validation-metadata.zip：去識別驗證摘要，執行程式不需要它。

可在 PowerShell 核對下載檔：
Get-FileHash .\InkPick-v1.8.0-rc.17.exe -Algorithm SHA256
將結果與同版 SHA256SUMS 裡的 EXE 那一列比對。
不要把其他版本的 EXE、ZIP 或校驗檔混在一起。

二、整列搜尋與 A／B 核對
----------------------------------------
整列搜尋：整區輸入值逐列核對發票

A 是來源軟體的一整塊輸入資料，可以含多列、每列多個數值；B 是另一套軟體中可見的發票位置。預設「框選整區／逐列核對」：先辨識 B 的文字與位置，再讀取 A 整理各列，將目前列的每個值逐一對照。藍色箭頭標示目前 A 列，核對結果顯示在實際找到的 B 文字旁。

每個 A 數值最多採用一個 B 位置，同一個 B 文字位置也只能分配給一個值。原有「逐欄框選」可切換使用，同樣遵守位置不重複分配；另一個獨立功能「固定位置 A／B 核對」維持原操作。

第一次設定

1. 讓來源資料與發票同時顯示於主螢幕，控制窗移到讀取範圍外。點浮窗「整列搜尋」，或系統匣的「整列搜尋（數值核對發票）」。
2. 保持「框選整區／逐列核對」，按「框選輸入值範圍（A）」，一次圈住要核對的多列資料，不需要逐欄建立數值。
3. 按「框選發票位置（B）」，圈住共用的可見發票區；A 與 B 不可重疊。框好後會顯示「已框選」，可按旁邊「預覽／調整」確認內容。
4. 預設「數值核對／相似提醒」及「日期換算（民國／西元）」。按「開始搜尋」，控制窗收起，A 目前列旁出現藍色箭頭，B 顯示找到或相似的值與百分比。
5. 按「恢復介面」，用「上一列／下一列」切換已辨識出的列。箭頭及目前列的全部數值一起更新；整個 A 範圍與 B 範圍不移動，到了首尾會停用對應按鈕。
6. 在發票軟體切換下一張時，B 的框可以保持。搜尋中的像素檢查發現框內內容改變會重新讀取 B；想立即重讀，按浮動「手動辨識」。

所有來源都要保持可見。工具不能讀到被遮住、最小化、捲動區外或螢幕外的內容，也不替其他軟體點列或翻頁。

A 會取出哪些值

整區模式依 OCR 文字行的位置分組，一次最多 100 列、每列最多 20 個值。會取十進位數字、支援的完整日期，以及含數字的西文識別碼；純中文姓名或只有英文字母的內容不會自動變成數值欄。要核對這類一般文字，切換「逐欄框選」，使用「框選數值／新增數值欄位」逐個設定，最多 20 欄。

同一個 OCR 行可以拆出多個值，但它們仍保留同一個真實文字行框，不捏造每個字元的位置。分組依畫面上文字行的高低及重疊判斷，沒有加入表格結構模型；合併儲存格、斜字、錯行、黏在一起的欄位或 OCR 未提供有效位置時，請縮小範圍或改逐欄框選。超過上限或部分資料無效時會提示需確認，不把截斷內容算成完整通過。

「上一列／下一列」在整區模式切換實際辨識到的列；逐欄模式則依「列高／間距」（1–500 螢幕像素，初始 30）一起平移各 A 框。兩種操作都不會替來源程式按鍵或捲頁。

預覽與調整位置

A、B、跟隨表格及逐欄位置旁都有「預覽／調整」。點擊會先暫停搜尋、隱藏標示，再取一張主螢幕完整影像放在記憶體，供移動框選位置；下方另顯示選取範圍的裁切預覽。

- 拖曳藍框移動，拖曳右下角改大小；「放大／縮小／顯示全畫面」只改預覽倍率。
- 箭頭按鈕每次微調 1 像素，按住 Shift 為 10 像素；不能移出影像或縮成無效範圍。
- 「套用位置」才更新範圍；「取消」保留原位置。兩者都不會自動恢復搜尋，確認後再按「開始搜尋」。
- 預覽是當下靜態畫面，來源之後改變不會在對話框內持續刷新。關閉／取消會清除完整影像及裁切圖，只保留範圍；不寫入圖片檔、歷史、剪貼簿或內容 Log。

找到、相似與位置分配

| 結果 | 意義與處理 |
| --- | --- |
| 綠色「找到」 | 文字／數值相符，或支援的日期換算為同一天，且沒有待確認訊號 |
| 橘色「相似／需確認」 | 顯示一個可用的近似候選，或辨識／位置仍需核對；人工採用近似也不變綠色 |
| 紅色「未找到」 | 沒有符合候選，不沿用前一列位置 |
| 「多處符合」 | 多個確切位置，回控制窗選一處再按「採用」，不自動取第一筆 |

確切符合及合法日期等價優先於近似。近似可以先顯示一個未被其他值使用的候選，方便直接看到差異；仍是橘色暫定結果。每個 B 位置只分配一次，其他值若沒有剩餘位置會提示需確認。高度重疊的 OCR 框也視為同一處；同位置出現互相矛盾的讀字結果不能算確定命中。

人工改選時，最新選擇接管同階段衝突的位置，原先那筆回到待核對，其他選擇保留；確切符合仍優先於近似。

位置精度仍是 OCR 文字行：若 B 把好幾個值讀成同一行、只有一個大文字框，不能把它假裝成多個獨立可分配位置，也不能保證指出行內重複數字中的某個字元。遇到這種情形，縮小 B 或改顯示倍率後重讀。

數字近似與百分比

百分比是「相同數字位數 ÷ 全部數字位數」，格式符號不算分母，不是 OCR 正確機率，也不是金額誤差比例。100% 但 OCR 低信心仍可能是橘色。畫面最多一位小數並向下截斷，不將近似四捨五入為 100%。

兩模式都要求單一十進位片段、至少兩位數字、位數及格式相同，保留正負號、貨幣符號、括號、小數點、千分位、百分號與前導零數量。不把 O／I 猜成 0／1，也不套用一般複製的標點清理。

| 模式／例子 | 處理方式 |
| --- | --- |
| 整區模式 | 相同位數至少 60% 才列近似，可有多位不同；全部近似都需確認 |
| 12345 對 12346 | 80%，橘色 |
| 12345 對 12399 | 60%，整區模式可列橘色候選 |
| 12 對 13 | 50%，整區模式不列近似 |
| 逐欄模式 | 沿用只差一位數字的規則，12 對 13 可顯示 50% 橘色；不代表高度接近 |
| 1.23 對 123、-100 對 100、1,000 對 1000、01 對 1 | 位數／格式不同，不列數字近似 |

一般文字沿用 95% 近似門檻，先統一 Unicode 等價組合（NFC），忽略一般空白標點，保留大小寫及全形／半形差異。西文詞與識別碼要求完整邊界，Ann 不命中 Anna、123 不命中 INV123；中文可在行內找子字串。「逐字完全相同」停用全部近似與日期換算。

民國／西元日期

預設開啟「日期換算（民國／西元）」。例如 A 的 115/10/12 和發票的 2026-10-12 代表同一天，顯示 100%，控制窗註明「日期換算」。仍保留兩邊原文；低 OCR 信心不因換算而變成確定命中。取消勾選可停用換算；「逐字完全相同」模式也會停用換算。

支援範圍：

- 「民國／中華民國」（也接受「民国」）後接 1–3 位且大於 0 的年；未寫年制的三位年視為民國，不能以前導 0 開始。
- 「西元／公元」或未寫年制的四位年視為西元，不能以前導 0 開始。
- Y/M/D、Y-M-D 或中文年月日，例如 115年10月12日；月份與日期各 1–2 位，必須是有效日期。
- 支援全形數字、斜線、連字號，以及已知中文年制後的冒號，例如 民國：115/10/12、西元:2026/10/12。

不猜未標年制的一／二位年、缺年月日、無效閏日或錯字；也不把時間、日期區間、嵌入識別碼、農曆、前紀元、AD／BC／ROC 等英文年制或年制括號當成可換算日期。上述不支援的年制前綴不會丟掉後硬套支援格式。

發票上的文字與透明度


ZIP 內的示意圖只用合成資料，不包含使用者發票，不代表模型準確率。

標示只顯示 A 原值及百分比，優先放在已選定 B OCR 文字框下方；相似候選下方太擠時，會嘗試緊鄰文字框的右側或左側。維持文字點擊穿透，可操作下方文件。文字較長會省略，完整內容在控制窗。OCR 只給文字行時，位置也只精確到那一行，不能保證指出同一行重複數字中的某一個。

若尚未選定候選、找不到，或下方／可用側邊位置會重疊其他已選定文字框或標示，就不憑空放一個位置；「恢復介面」會提示未展開筆數，可回控制窗查看。

「標示背景透明度」範圍 0–100%，預設 100%：背景全透明，只保留清楚的數值與百分比；0% 使用白底。它只改標示底板，不把文字一起變透明，不觸發新辨識，也不會因調整設定恢復已暫停的結果。

「標示置頂」預設開啟，控制文字及「手動辨識／恢復介面」兩個小按鈕；控制窗保持一般視窗。切回來源程式或擷取恢復後依原設定維持置頂，不需重開。要暫停先按「恢復介面」，再按「暫停」。

自動輪次與手動辨識

開始後會按設定間隔擷取畫面，檢查內容是否改變。A、B 全部未變時略過 OCR；B 未變而 A 換列／內容改變時，保留一份有界的 B OCR 記憶體快取，只重新辨識 A。整區模式換列會重讀 A 整區，B 仍可重用；B 的位置相同但發票內容改變時，像素摘要不同就重新 OCR B，不沿用舊發票結果。快取仍核對像素與辨識設定，不把相同座標當成相同內容。

搜尋中可直接按浮動「手動辨識」，或控制窗同名按鈕：保持座標，撤銷舊一輪，重新辨識發票 B 及 A，即使畫面沒變也重新讀取。快速重複按不另開並行模型，過期回覆不覆蓋新結果。暫停／關閉時手動辨識不可用，不會暗中重新開始。

每次擷取前同時隱藏標示與兩個浮動按鈕，避免 OCR 讀到自己；恢復時可能短暫閃動。透明或置頂不能讓工具讀到被其他軟體遮住的原文。

手動換列與選取列跟隨

整區模式用「上一列／下一列」切換實際 OCR 列並移動目前列箭頭，整個 A／B 範圍保持；逐欄模式則依「列高／間距」（1–500 螢幕像素，初始 30）一起平移各 A 框並重新搜尋。這只移動讀取框，不替其他軟體點列或捲頁。手動換列會暫停自動跟隨；超出範圍不沿用舊結果。

自動跟隨步驟：

1. 先完成 A／B 框選，整區模式先搜尋一次取得可定位的目前列，再恢復介面並暫停。在來源軟體選取基準列，保持清楚均一的選取底色。
2. 按「框選輸入表格（換列用）」，只圈可跟隨的來源表格，避開工具列、固定標題及同色面板。
3. 設定列高，按「校正目前選取列」，在 3 秒倒數內回到來源軟體選好基準列。
4. 開啟「自動跟隨表格」再開始搜尋。新底色列連續兩次檢查穩定後，整區模式切換目前列，逐欄模式把 A 框一起移到新列；同一 Y 座標換入新內容也會更新。

這是畫面底色追蹤，不讀取其他軟體的資料庫、控制項或語意游標。底色消失、多個可能選取列或越界時不猜位置；白底、斑馬紋、多重選取、動畫、主題改色或不等高列可能無法可靠跟隨。改用手動換列，或重新框選／校正。無法確認新列時仍按間隔檢查；要停止等待請按暫停或關閉。

來源改縮放、移動欄位或改變列距後，請重新確認位置與列高。新增／移除欄位、改框或改列高會撤銷先前校正。要處理下一頁，先在來源軟體操作，必要時重新框選。

相關 Repo 與本版選擇

本版沿用既有 OCR 文字行與位置，以有上限的 Python 標準庫規則分列、取值與分配，沒有加入新原生套件或模型。
- RapidFuzz（https://github.com/rapidfuzz/RapidFuzz）：可加速字串近似，不提供表格位置；Windows 原生依賴另需驗證，本版未接入。
- PaddleOCR／PP-Structure（https://github.com/PaddlePaddle/PaddleOCR）：可分析版面／表格結構，需額外模型及離線推論封裝；不等於已證明提升本工具文字辨識率。
- Table Transformer（https://github.com/microsoft/table-transformer）：表格偵測／結構需搭配 OCR，Repo 已封存，另需 PyTorch／權重，本版未接入。
後續若需儲存格或字元定位，須另外驗證定位、辨識率、速度與離線體積，不能以目前文字行框冒充。

停止、暫存與保留資料

開窗不自動搜尋；開始或手動換列才啟動，校正另做一次取樣。暫停、改框、清除或關閉停止後續工作、取消排隊並清除過期標示；已進入原生 OCR 的單次呼叫需先返回。晚到回覆不能重開視窗。關閉後不在背景繼續跟隨。

模式共用既有離線 OCR 工作者，不另開模型。每輪取包住已選範圍的共用快照，再於記憶體裁出 A／B；範圍間畫素可能短暫存在，不留檔。結果發表前再次檢查畫面，內容變更就丟棄該輪。

座標、校正、結果與有界快取只留本次執行記憶體，當輪影像完成／取消後釋放。不把 A／B 圖片或文字寫入歷史、剪貼簿、匯出、內容 Log 或新截圖檔，也不上傳。不提供跨次啟動的配置復原；一般 OCR 歷史、90 天封存及 Log 規則維持原樣。

找到相同字串或同一天，仍不保證原始資料輸入正確。實際同版驗證範圍見 驗證說明 與 Release 的 validation metadata。

固定位置 A／B 核對：多組結果同時呈現
每組比較主螢幕上兩個固定位置的 OCR 文字，例如兩個系統的訂單編號。
只有手動開始後才掃描，開啟應用程式或核對窗不會自行開始。
一般窗預設 348 × 560，「迷你」結果窗為 320 × 300（最小 320 × 280）。
多組時每組各有一張結果卡，同時列出名稱、A、B 文字、狀態與上次辨識時間。
一般尺寸可完整看到約 3 組，迷你尺寸至少 2 組；更多組別直接捲動查看。
不用切換第一組、第二組才能看到結果。

組別設定
1. 點浮動窗「A／B 核對」，在「設定組別」選一組，分別選取 A、B 範圍。
   Esc 取消這次框選。同組兩區須位於主螢幕，且不能重疊。
2. 按「＋」新增組別，例如「訂單編號」「金額」，各自設定 A、B。
   最多 20 組，至少保留 1 組；「⋯」可「更改組名」或「移除此組」。
3. 任一組尚未選好兩區時，先完成或移除該組才能開始。
4. 把核對窗移到所有組別的框選範圍外，按「開始全部」。
5. 「設定組別」或點選結果卡只決定要編輯位置、管理或查看全文的組別；
   其他組結果不會隱藏，也不會改動正在辨識的位置或中斷整批。

一起看結果，依序做辨識
- 所有組別共用一條擷取與 OCR 管線，依建立順序處理，不會平行開多個引擎。
- 每組 A、B 取自同一張快照；組與組依序擷取，不代表全部組別同時取樣。
- 卡片各自更新，不改其他組文字、時間、視窗尺寸或捲動位置，也不搶焦點。
- 綠色「一致」：兩側成功辨識，依所選規則比較後相同。
- 紅色「不同」：兩側成功辨識，但文字不同。
- 琥珀色「待確認」：任一側空白、失敗或仍需人工核對；兩側都沒讀到字不算一致。
- 卡片可另外顯示「檢查／辨識中／未變／暫停」；時間仍是上次實際辨識的時間。
- 每區文字預設一行，長文省略；滑鼠停留可查看前 800 字。
  先選定組別，再按「查看全文」閱讀完整內容；迷你模式會先還原一般尺寸。
  「收合全文」回到摘要。單組時保留原本兩區的結果版面。
- 系統匣優先顯示任一組的差異；沒有差異但還有未確認結果時顯示待確認。

畫面不變時
- 每批完成全部組別後預設等 2 秒再檢查，可調為 1–60 秒，辨識耗時另計。
  組別越多，一批所需時間越長。
- 每組只比較自己的 A、B 像素摘要；兩區未變就跳過該組 OCR，保留文字、時間與次數。
- 只有某一組變動，不會讓其他未變組別重辨；框外變化不觸發。
  框內游標閃爍或動畫也算變化。
- 等待期間仍會按間隔檢查畫面；暫停或關閉後連畫面檢查也停止。
- 想重讀相同畫面時，先暫停再開始。

規則與操作
- 預設忽略空白、標點及其他符號，只比文字與數字，保留附加音標並統一等價組合形式。
  「訂單：AB-123」與「訂單 AB123」相同；大小寫及全形／半形不會自動統一。
- 「逐字比對」連空白、換行和標點一起核對。金額、負號有意義時請用逐字比對，
  因為預設可能將 1.23 與 123、+100 與 100 視為相同。
- 比對規則套用全部組別，與剪貼簿複製清理互相獨立。
- 新增、更名、移除組別、重選範圍或改規則會先暫停全部，修改完再手動開始。
- 「置頂」可隨時取消，可自由拖移及調整大小。「迷你／還原」只切換呈現方式，
  不另開辨識工作。手動拉短至高度低於 540 時也用迷你版面，拉高至 560 以上回一般版面。
- 按「還原」保留目前位置與先前一般尺寸；「查看全文」會先還原再展開。
- Windows 標題列最小化會隱藏視窗，但繼續已啟動的核對；想保持小窗可見請用「迷你」。

停止與資料
- 暫停、關閉或退出會停止核對計時器，清除各組摘要及待處理影像，丟棄晚到結果。
  已進入原生呼叫的單次運算需先返回，但不再補辨、處理下一區或下一組。
- 單組一次核對超過 30 秒會暫停整批。關窗後重開保留本次組別，須手動開始。
- 組別、位置與結果只存在本次執行記憶體，退出後需要重設；不改剪貼簿、不寫歷史，
  不新增核對截圖、文字或內容 Log。等待下批只留短摘要，沒有畫面快取。
- 請保持所有來源可見；捲動、移動來源或改變縮放後應重新選取。
  顯示器配置變動會清全部位置、保留組名。遮住任一組時會暫停並提示移開。
- 比較的是 OCR 文字，不保證原始內容正確；不能讀取鎖定畫面或被遮住的原內容。

三、文件套版：PDF／圖片逐頁填入文字
----------------------------------------
這個功能適合同一版型的表單、通知單或掃描圖片。
先在第一頁定義幾個辨識位置，再讓每一頁填入同一份文字模板。
檔案只在本機讀取與辨識，不會上傳。

基本流程
1. 點浮動窗「文件套版」，或在系統匣選「文件套版（PDF／圖片）」。
2. 點「匯入 PDF／圖片」，選一份或多份 PDF／圖片。
   多個檔案依匯入順序接成一批，PDF 內仍按照原來頁碼排列。
   用預覽上方頁面清單、上一頁與下一頁確認順序。
3. 單檔預設上限 100 MB；可在視窗上方改為 1–1024 MB。
   這裡的 MB 以 1024 × 1024 bytes 計算，設定會保留到下次啟動。
4. 在第一頁的「框選欄位」分頁選「辨識1」，拖曳框出第一段文字。
5. 按「新增欄位」建立「辨識2」，再框第二段文字。
6. 切到「文字模板」，輸入想輸出的格式，例如：

   文字｛辨識1}文字測試{辨識2}

7. 按「開始辨識」。完成後在「逐頁核對」檢查欄位內容，
   在「TXT 預覽」查看實際輸出，最後按「複製結果」或「匯出 TXT」。

範例
假設第一頁的「辨識1」是「王小明」，「辨識2」是「1,234」，
上面的模板會輸出：

文字王小明文字測試1,234

每一頁會各套用一次，頁與頁之間加入兩個換行，以空行分隔。
如果模板末尾本身有換行，也會保留，因此可能看到較多空行。
模板的固定文字、標點、空格及換行都會保留。
模板、TXT 預覽、複製結果與匯出保留原文，不套用一般 OCR 的複製清理。

命名與插入欄位
- 選取欄位，在名稱欄輸入「姓名」或「金額」，按「重新命名」。
- 模板裡原來對應的欄位名稱會同步更新。例如可改成：

  姓名：{姓名}
  金額：{金額} 元

- 同一欄位可以出現好幾次；每頁只辨識一次，再填入對應位置。
- 雙擊欄位名稱，或按「插入所選欄位」，可插入模板游標所在處。
- 支援半形 {姓名}、全形 ｛姓名｝，也支援混用的 ｛姓名}。
- 要固定顯示大括號，可輸入雙括號。例如 {{固定文字}} 輸出 {固定文字}。
- 欄位名稱不能重複，也不能包含大括號、換行或控制字元。
  名稱拼錯、括號不完整或尚未框選時，會提示修正。

第一頁與逐頁位置
- 第一頁的位置是所有頁面的共用位置。
- 如果第二頁、第三頁沒有另外框選，就一直沿用第一頁，不需要每頁重選。
- 第二頁位置不同時，切到第二頁，確認範圍是「只改這一頁」，
  再重新框選要調整的欄位。該頁其他欄位仍沿用第一頁。
- 第三頁未調整時仍用第一頁的位置，不會沿用第二頁的例外。
- 「此頁套用第一頁」會清除目前頁面所有欄位的例外位置。
- 後續頁面也可改選「所有頁共用」來更新共用位置；
  已另外設定過的頁面仍保留自己的例外。
- 欄位依頁面比例套用。同一版型的不同圖片尺寸可以共用，
  但版面移動、旋轉或內容跨頁時，不會自動追蹤欄位，仍要調整。

清除框選與清空文件
- 框錯位置時，先選欄位，再按「清除框選」。
- 「所有頁共用」會清掉這個欄位的共用位置及各頁例外，需要重新框選。
- 「只改這一頁」只清當前頁的這個欄位，不會自動改用第一頁的位置。
  可重新框選，或按「此頁套用第一頁」恢復當前頁所有欄位的繼承。
- 清除框選後，舊辨識結果作廢；模板用到的欄位必須有可用位置，
  才能重新開始辨識。
- 要換一批文件，按視窗上方「清空文件」並確認。
  它會清掉匯入頁面、全部欄位位置、逐頁例外及結果，保留欄位名稱和文字模板。
  再次匯入後需要重新框選；原始檔、已匯出的 TXT 與剪貼簿不受影響。
- 載入或辨識中也能清空文件，尚未完成的舊工作會取消，晚到結果不會回填。
  正在執行的原生運算仍須先返回；不會繼續處理其餘舊頁面。

縮放與精確位置
- 預覽上方有「−」、目前比例、「＋」、「適合視窗」、「100%」及「拖曳移動」。
  按「−」「＋」縮放；「100%」回到百分之百，「適合視窗」顯示整頁。
- 放大後開啟「拖曳移動」，可用左鍵拖動頁面；關閉後左鍵恢復框選。
  一般滾輪或捲軸可移動頁面，滑鼠中鍵也可拖動。
- Ctrl 加滾輪或 Ctrl 加加號／減號可縮放；Ctrl+0 適合視窗，Ctrl+1 回到 100%。
- 手動縮放比例會保留到切換頁面或調整視窗大小後；
  適合視窗模式會依視窗重新調整。載入預覽或辨識時，縮放與框選暫時停用。
- 右側左／上／寬／高是頁面百分比；輸入後按「套用位置」，
  可用鍵盤設定範圍。範圍必須在頁面內，寬、高不能是零。
- 框選時請包含完整筆畫，盡量避開不需要的鄰近文字。
  放大預覽不會改善原始低解析圖片的內容。

核對、停止與輸出
- 在「逐頁核對」雙擊欄位，或按 F2／Enter，可修改該格的文字，支援多行。
- 按確定後，「TXT 預覽」會更新。
- 待核對的欄位請對照原圖；失敗或未完成的欄位會阻止輸出。
  可重新辨識，或手動補上正確內容。
- 某格確定應為空白時，可進入編輯視窗，保留空白再按確定，明確確認這一格。
- 「複製結果」會複製 TXT 預覽的全部內容，再到目標程式 Ctrl+V；不套用一般 OCR 的移除／替換。
- 「匯出 TXT」預設開在 data\exports，也能選擇其他資料夾。
  檔名須以 .txt 結尾，UTF-8 含 BOM，可用 Windows 記事本開啟。
- 不能選擇匯入原檔或其別名當輸出，避免改掉原始文件。
- 匯入、框選、辨識、停止、關閉文件視窗都不會自動改動剪貼簿。
- 按「停止」或在辨識中關閉視窗，會取消尚未完成的工作。
  目前正在執行的原生運算必須先返回，之後不會繼續剩餘頁面。

支援與上限
- PDF、PNG、JPEG、BMP、TIFF、WebP；多頁圖片按其頁面順序處理。
- 每批最多 500 頁、32 個命名欄位。
- 一般已填 PDF 表單可顯示內容；加密 PDF 請先解除密碼保護。
  XFA 動態表單請先列印或另存成一般 PDF。
- 圖片解析度、頁面尺寸與渲染另有記憶體上限，過大時請拆檔或縮小圖片。
  程式逐頁讀取、逐欄位排隊，不會一次把整份 PDF 全部解成圖片。
- 匯入原檔只讀，不會自動加進截圖歷史，也不另存輸入副本。
  處理中若原檔被移動或修改，請重新匯入。
- 欄位、模板、逐頁位置與結果只保留在本次程式執行中，
  不會保存成永久專案。結束程式前請匯出需要的 TXT。
- 重新匯入其他檔案時，保留共用欄位與模板，清除舊的逐頁例外與結果。

四、從螢幕擷取文字
----------------------------------------
預設仍是「框選螢幕 → OCR 辨識 → 全文自動複製」。
1. 點浮動窗「擷取文字」，或按 Ctrl+Shift+O。
2. 拖曳框出要辨識的螢幕範圍，Esc 可取消。
3. 等待完成，這次範圍內的全文會自動複製。
4. 切回要貼上的程式，按 Ctrl+V。

只想複製其中幾段
1. 開啟浮動窗右上角設定。
2. 進入「剪貼簿 → 辨識完成後」，改成「先選文字再複製」，按「儲存」。
3. 儲存後立即生效，不需重啟；第一步仍然先框選螢幕、再執行 OCR。
4. 完成後，在選取視窗點選原圖的文字框、拖曳框選，或勾選右側文字。
   Ctrl 拖曳可加選，空白鍵可切換清單勾選。
5. 下方「複製內容」可以修正文字或反白一小段。
   按「複製」或 Ctrl+Enter 才寫入剪貼簿；「全選」可選整份結果。
6. 「稍後再選」、Esc 或關閉視窗都不複製。

要恢復原操作，將設定改回「自動複製全部文字」。
新安裝與沒有這個設定的舊設定檔，預設皆是全文自動複製。
螢幕 OCR 結果與截圖照設定留在本機歷史；只複製一段不會刪掉其餘內容。
沒有保留原圖時仍可勾選文字。選取或預覽修改不會把整份結果標成已核對。
取消後可到歷史開啟編輯器，再反白／複製需要的文字。

失敗、空白或過期的辨識不會清空剪貼簿。
若較早 OCR 尚未完成，而你已在拾字筆的手寫或歷史手動複製其他內容，
晚到的結果只保存到歷史，不會覆蓋這次手動複製。

複製清理：移除或替換

開啟「設定 → 剪貼簿 → 複製清理」，每列先勾選要啟用的項目，再選「移除」或「替換」。選替換後會出現文字欄，直接輸入自己的字串，按「儲存」立即生效；「取消」不保存草稿。新安裝四列都不啟用，舊有勾選狀態保留，原本的移除行為不會自行改為替換。

| 項目 | 處理範圍 | 替換例子 |
| --- | --- | --- |
| 逗號 | 半形 ,、全形 ， | 替換成 ・：甲,乙，丙 → 甲・乙・丙 |
| 撇號 | '、‘、’、＇ | 替換成 -：A'B → A-B，其他引號不由這一列處理 |
| 換行 | CR、LF、CRLF 與支援的 Unicode 換行；CRLF 算一次 | 替換成  / ：兩行「甲」「乙」→ 甲 / 乙 |
| 所有標點與空白 | Unicode 標點及空白，含半形／全形空格、Tab、換行 | 選移除：「 您好，　世界！ 」 → 您好世界 |

替代文字是原樣插入的字串，不解讀成正規表示式、變數或程式；最多 64 個 Unicode 字元，可含空格、中文或 emoji，不能含 Tab、換行、控制字元或不完整代理碼。留空等同移除。取消勾選或切回移除會保留先前輸入，日後可再切換；需要修正的啟用規則會留在設定窗，不先寫入其他設定。

同時開啟時，逗號／撇號／換行各自的規則優先於「所有標點與空白」。替代文字不會再被其他規則清理。例如逗號替換成 , ，就會保留這個逗號與空格，即使也開啟所有標點移除。每個原始字元各處理一次，連續三個空格替換成 - 會得到 ---。

多筆歷史複製原本以兩個換行分隔。單獨使用「換行 → 移除」仍保留筆與筆的空行；明確使用換行替換時，分隔的兩個換行也各替換一次。「所有標點與空白 → 移除」會去掉分隔空行，但更優先的換行替換仍可保留自訂分隔。

清理套用一般 OCR、歷史／編輯器的複製，以及「貼上最後一筆」準備送出的文字。歷史原文不變；文件套版的複製／TXT 預覽／匯出與手寫候選皆維持原樣。A／B 核對使用自己視窗的比較規則。清理後若只剩空白或空字串，不會清空舊剪貼簿。所有標點規則會處理小數點與半形負號，例如 -1.23 選移除後成為 123；數學／貨幣符號則不一概視為標點，處理金額前請確認。

五、截圖、手寫與歷史
----------------------------------------
截圖
- 點「截圖」或按 Ctrl+Shift+S，可儲存框選圖片。
- 是否接著辨識，依「設定 → 擷取 → 截圖後自動執行 OCR」。

手寫單字
1. 點「手寫」，在方格內一次寫一個字。
2. 停筆後顯示候選，點正確的字即可複製，再自行 Ctrl+V。
3. 「撤銷一筆」或 Ctrl+Z 可退回一筆，「清除」可全部重寫。
4. 原始與置中筆畫各取前 30 字，去重最多 60 字。
   按「展開」可查看更多；方向鍵移動，Enter／空白鍵複製。
5. 沒有所需的字時，可按「影像補辨」，用內含 OCR 增補最多兩個候選。
   再按一次可取消。這不保證補準缺字，也不會自動向別的程式輸入。

候選區清空或更新時會保留高度，書寫中不會自動捲動；
同一筆的座標保持固定，避免畫布突然變大或移動造成筆畫跳位。
展開、收合與選字複製方式維持原操作。

手寫候選保留所選原字，不經簡繁轉換或一般 OCR 複製清理。
筆畫字庫有 11,853 字，含「龘」，不含「尞、𠮷、𠀋」，
也缺少「內、吳、戶、辦、嚐」等常用字。影像補辨使用另一套 OCR 字庫。
候選順序與分數不是正確率，未收錄的字不會自動猜成其他字。

歷史紀錄
- 點浮動窗「歷史紀錄」，可搜尋、編輯、釘選、刪除、複製與匯出。
- 歷史視窗的「匯出」支援 TXT、CSV（Excel 相容）、JSON 與 ZIP。
  CSV 使用 UTF-8 BOM，包含文字、來源、OCR 狀態及信心分數，預設存入 data\exports。
  只有手動匯出才會產生 CSV；文件套版目前輸出 TXT，Release 不夾帶使用者匯出的 CSV。
- 浮動窗沒有搜尋框；Ctrl+Shift+Q 會直接開啟歷史搜尋。
- 文件套版匯入的 PDF／圖片與結果不會自動出現在這個截圖歷史。

90 天自動封存
- 到「設定 → 一般 → 自動封存」調整天數，預設 90 天；0／停用會關閉，儲存後立即套用。
- 程式啟動與每日檢查，依最後修改時間封存已滿天數的歷史；每批最多 200 筆。
  查看或複製不延後日期；修改文字、筆記、標籤關聯或手動還原會更新修改時間。
- 釘選、已刪除、已封存或辨識中的紀錄不納入；沒有資料時結束本次檢查，不持續掃描。
- 封存不刪除文字、原圖或附件，也不會釋出附件占用的磁碟空間。
  可在歷史視窗「已歸檔」分類查看，右鍵選「取消歸檔」還原。
- 一般「刪除」是軟刪除；「清理已刪除」才永久刪除該資料及附件，另存的匯出副本不跟著刪。
  本版沒有依總筆數或封存天數自動永久刪除的功能。
- 設定變更或退出會取消後續批次；關閉前會等已接受的資料庫工作結束。
- 浮窗與主控台的封存、釘選、刪除與編輯會同步刷新，保留目前搜尋與分類。
- 舊版異常中斷後仍標為辨識中的紀錄，缺少程序擁有者資訊，不能安全地自動認定為死工作；
  本版保留並排除於自動封存之外，需要時可手動重辨。

Ctrl+Shift+F      全螢幕擷取

六、檔案位置、暫存、附件與 Log
----------------------------------------
浮動窗底部「檔案位置」會開啟目前實際使用的資料夾。
「截圖與附件」「紀錄與設定」有子選單；尚未產生的位置會停用。
選單只開資料夾，不會刪檔。

預設在 EXE 同層的路徑：
- data\captures：原始截圖，依年月分資料夾。
- data\annotations：圖片編輯與標註附件。
- data\thumbnails：歷史清單的圖片縮圖。
- data\exports：歷史匯出與文件套版 TXT 預設另存位置。
- data\app.db：歷史文字、OCR 結果與筆記；旁邊可能有執行中的 WAL／SHM 暫存。
- config\settings.json：設定，另可能有備份或儲存中的暫存檔。
- logs\app.log：執行記錄，每日輪替，最多保留 30 份舊 Log。
- 程式暫存：這次 EXE 在 %TEMP% 解開的 _MEI… 資源資料夾，
  包含程式、PDF 引擎與模型，正常退出後由執行器清理；執行中不要刪除。
- 程式資料夾：目前使用的程式主資料夾。

關掉程式不會自動刪除 data 的截圖、附件、匯出或歷史。
Log 有獨立保留週期。請先退出程式，再備份、移動或整理資料。
若以前自訂過資料位置，依「檔案位置」顯示的實際路徑為準。
自訂 data 位置不會把設定與 Log 一起搬走；設定與 Log 仍跟隨程式根目錄。
若設定 DESKTOP_OCR_HOME，則以該位置為根目錄。
在另存對話框自行選到別處的檔案，仍留在當時選的路徑。

七、升級、備份與資料隱私
----------------------------------------
1. 先從系統匣退出舊程式，等待背景工作結束。
2. 備份原來的 config、data，以及需要保留的 logs。
3. 把新版 EXE 放回原來可寫入的資料夾，保留原有資料，
   不要用新版 ZIP 覆蓋自己的資料。
4. 若換資料夾，請一起移轉原有 config／data。
5. 更新舊捷徑；自動啟動若還指向舊 EXE，先在新版取消開機啟動並儲存，再勾選並儲存。

- 新安裝預設關閉剪貼簿監看；舊設定會保留。
  只有需要記錄外部複製文字時，才到「設定 → 剪貼簿」啟用。
  監看與文字收錄設定儲存後立即生效；停用或暫停會卸除監聽器。
  重新啟用只收錄之後的剪貼簿變化，不回填目前內容；浮窗與系統匣的暫停狀態同步。
- 四種複製清理預設關閉，可各自選移除／替換，儲存後影響一般 OCR／歷史複製及「貼上最後一筆」。
  不改原始歷史、手寫候選、文件套版複製、模板、TXT 預覽或匯出；單獨換行移除保留紀錄分隔，
  換行替換會處理分隔空行，個別規則優先於所有標點與空白。
- 本機歷史、截圖、附件、匯出與 Log 沒有加密。
  文件套版匯出的 TXT 也可能包含姓名、帳號等個人資料。
- 不要把整個 data、config 或 logs 直接附到公開錯誤回報。
  分享前請移除實際文件、帳號、個人路徑與無關文字。
- OCR、PDF／圖片處理與手寫不需要上傳圖片或筆跡。
  若啟用 Windows／第三方剪貼簿同步，複製內容可能被該服務同步。
- 新版公開下載包排除原始 JUnit、錯誤堆疊與私有建置報告，
  公開驗證摘要只保留固定允許欄位。
  已知部分舊 Git 歷史與舊 Release 報告仍有測試機名稱／絕對路徑，
  新版遮蔽不會讓舊資料自動消失；這不代表發現了真實憑證或私人 OCR 文件。

八、常見問題與辨識限制
----------------------------------------
找不到浮動窗：
先查看右下角系統匣拾字筆圖示，或按 Ctrl+Shift+Space。

尚未能按「擷取文字」：
第一次啟動要解開資源並載入模型，請先等待。
若狀態顯示無法辨識，可從系統匣退出、等工作結束後重開，再查看 Log。
不需要為了這個動作連網下載模型。

文件套版「開始辨識」不能按：
檢查模板名稱、括號及框選範圍；每個引用欄位都必須有位置。
名字可重複引用，但欄位定義的名稱不能重複。

PDF 或圖片不能匯入：
檢查每個檔案大小、500 頁上限、影像解析度及檔案是否損壞。
加密 PDF 請先解除密碼，XFA 請先轉為一般 PDF。
上限提高到 1024 MB 也不會取消解析度或頁數的保護。

辨識內容不正確：
確認框選沒有切掉筆畫，必要時逐頁調整位置。
OCR 可選 PP-OCRv6 Small／Medium，兩者都已內含；Medium 較耗記憶體，
不代表每一個字都更準。姓名、日期、金額與帳號務必自行核對。

已停止卻還沒立刻結束：
原生辨識不能安全地在任意時刻強制中斷，必須等目前運算返回。
程式不會再處理剩餘欄位。執行中請不要刪除輸入文件、資料庫或暫存。

無法匯出 TXT：
選擇可寫入的資料夾，以 .txt 結尾；不要選匯入原檔或其別名。
匯出失敗時，既有目的檔不會被未完成的寫入覆蓋。

九、套件漏洞與背景工作
----------------------------------------
沿用 rc.5 的套件修補：Pillow 13.0.0、setuptools 84.2.1、建置用 pip 26.2.2，
修正原版本命中的已知漏洞；pip 不隨 EXE 提供。
改用 OpenCV 5.0.0.93，避開舊 OpenEXR，並排除不需要的影片 DLL。
發布前會掃描 Linux／Windows 的實際 Python 套件清單，
任何漏洞、漏掃或查詢失敗都會停止發布。
掃描不涵蓋所有原生 DLL，也不代表不存在未知漏洞。

rc.12 另修補實際舊 payload 的 Qt 6.11.2 原生公告，
PySide6-Essentials 與 shiboken6 鎖定 6.11.3，成品必須核對實際 Qt 版本。
包含 Core CBOR 的 CVE-2026-107157／CVE-2026-105924，
以及 Network HTTP/2 的 CVE-2026-95620；不把未封裝 Qt5Compat 的公告算成產品命中。
Python 套件零發現不能替代這些原生 DLL 檢查。
舊 OpenSSL 3.0.16 經 SHA256 核對來自 CPython 3.12.10；
舊包另有檔名帶 -x64 的 OpenSSL 3.5.9，是 Qt 打包時外帶，不能混成同一來源。
Windows runtime 改用 Astral standalone CPython 3.12.16／20261026，
使用該鎖定發行包的動態 OpenSSL 3.5.9，建置時核對壓縮包 SHA256 與 PE 清單。
未使用的 Qt TLS plugins 與外帶 OpenSSL 另行排除，不修改使用者系統的 OpenSSL。

手寫回傳候選後會結束輔助程序，下一次書寫再啟動。
新筆畫、清除或重新辨識會取消過期手寫工作；OCR 閒置時改採阻塞等待。
系統匣、快捷鍵、資料庫與工作佇列等待，以及載入的 OCR 模型仍保留。
剪貼簿監看預設關閉，只有啟用後才會持續監看。
要全部結束請從系統匣選「退出」，只關閉功能視窗仍可從快捷鍵操作。
文件停止／清空會取消後續頁面，但已開始的原生 PDF／OCR 運算需先返回。
固定位置 A／B 核對與整列搜尋僅在按開始後持續執行；暫停或關閉停止後續工作，晚到結果丟棄。

Linux 會追蹤合成探針的程序樹網路系統呼叫；
整列搜尋等新增路徑的覆蓋與結果以同版驗證摘要為準，不沿用舊版數量；
Windows 另用同版 EXE 執行阻擋對外連線的功能檢查。
這不涵蓋所有 GUI 操作、任意外部文件及作業系統服務。
完整方法、限制與更新項目在 ZIP 內 docs/SECURITY_REVIEW.md，
實際發布結果在同版 validation metadata；原始追蹤與私人路徑不公開。

十、離線驗證與證據界線
----------------------------------------
GUI／原生／Defender 探針只在建置與驗證時執行，使用時不在背景啟動這些工具。
本版 GUI 會按面板／操作清單驗證指定入口、設定、歷史、編輯、選字、文件、
手寫、兩種核對、系統匣與退出流程，使用合成資料；不代表所有輸入都測過。
原生元件另核對實際 EXE／DLL／PYD 清冊、來源、匯入、簽章及 Defender 掃描。
原生稽核修正匯出表截斷，並依實際 Windows API-set／候選程式 manifest 的 SxS 解析。
只有證明 Windows 10+ 可提供受排除影響的符號及轉送鏈，
才從封裝排除明列的 43 個相容 stub 與 ucrtbase.dll；未證明則保留並由嚴格來源檢查擋下。
這 44 個舊檔的供應來源仍未知，不視為已核准；一般 msvcp／vcruntime／SSL 依賴保留。
這些是有界的中繼資料檢查，不表示新 Windows 成品或 Defender 已通過。
Defender 病毒碼必須在 72 小時內；建置機只在病毒碼過期時，
以 Microsoft 簽章有效的官方工具嘗試更新，最多 180 秒，再重新檢查相同門檻。
失敗或仍過期不算通過；不改防護設定，離線使用時不啟動更新或背景工作。
簽章未知不算有效，防毒不可用／逾時／未完成不算零偵測通過；
清冊完整也不等於每個檔案內所有靜態庫的完整 SBOM 或全部未知漏洞均已排除。
同版結果須對上 EXE 雜湊，不能拿舊版成功當作本版證據。
詳細的面板／操作表及限制在 ZIP 的 docs/VALIDATION_COVERAGE.md，
實際結果在同版 validation metadata；真人筆跡與乾淨實機仍須另驗收。

這是候選測試版，不保證任意文件或真人筆跡的辨識準確率。
發布流程會對同一份 Windows EXE 核對模型、PDFium、內嵌資源及檔案雜湊，
執行 OCR／資料庫、啟閉、手寫與文件探針，並在阻擋對外連線時重跑。
另外把單一 EXE 放入空白資料／暫存、清空 Python／Qt 環境設定、
只保留 Windows 系統 PATH 的環境，檢查是否依賴開發機的程式或模型快取。

Windows CI 主機仍可能預裝開發軟體。上述隔離測試不等於一台真正沒有預裝
Python／快取的獨立乾淨 Windows 10／11 電腦，也不代替觸控、混合 DPI、
多螢幕或使用者實際文件的現場驗收。
若一次檢查逾時，該次不計通過；重試必須核對同版 EXE 雜湊及原工作流程紀錄。
同版 validation metadata 記錄實際結果，不沿用其他版本的成功證據。

十一、僅供原始碼開發／建置者
----------------------------------------
一般離線使用電腦不需要執行這一節，也不要在使用電腦另外安裝依賴。
Linux 開發／測試使用 Python 3.12。Windows 發布固定使用 Astral
python-build-standalone 的 CPython 3.12.16／20261026 發行包，
供應來源是 Astral，並非 python.org 官方安裝器；RapidOCR 1.4.4 要求 Python < 3.13。
發行包只在建置時下載與核對，不在使用電腦下載或要求預裝 Python。
Windows 另需 Microsoft x64 C++ 編譯器，手寫 helper 使用 Release／MT 靜態 CRT。

Windows 發布建置請在原始碼目錄的 PowerShell 逐步執行，遇到錯誤即停止。
既有 Windows Python 3.12 只用來啟動 bootstrap；後續全部使用它印出的已驗證 python.exe。
目的地必須是系統暫存下的新目錄、不能位於 Repo 內，以下使用隨機新目錄：

$inkpickRuntimeDir = Join-Path ([IO.Path]::GetTempPath()) ('inkpick-python-' + [guid]::NewGuid().ToString('N'))

CI 的 bootstrap 使用：
python scripts/prepare_windows_runtime.py --destination "$env:RUNNER_TEMP/inkpick-python-runtime" --report artifacts/windows-runtime-inventory.json
GITHUB_PATH／GITHUB_ENV 只供同一 job 使用，不改全域 Python 或 PATH。
本機沒有這些 GitHub 檔案時不匯出環境，因此 pip／prepare／build 必須全程用 $inkpickPython。
Linux 來源驗證可使用 Python 3.12 執行上面相同的依賴、模型與探針指令，
將「& $inkpickPython」換成自己的 Python 3.12；不執行 Windows bootstrap 或 EXE build.py。

模型只在建置時從固定官方來源下載並核對 SHA256，應用程式首次執行不補下載。
Linux 無桌面測試可設定 QT_QPA_PLATFORM=offscreen。
